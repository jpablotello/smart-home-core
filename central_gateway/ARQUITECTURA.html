📐 Arquitectura General

El Gateway Central es un dispositivo ESP32 que actúa como hub de comunicación en un sistema de domótica distribuido. Sirve como puente entre dispositivos satelitales (usando ESP-NOW) y una red MQTT para control remoto y monitorización.

¿Cómo fluye la comunicación?

Resumen:

  • El gateway se conecta a Internet mediante Wi‑Fi (modo Station) y mantiene una conexión con un broker MQTT.
  • Los nodos satélite se comunican con el gateway usando ESP‑NOW (radio de corto alcance). Los satélites no acceden a Internet directamente.
  • Toda la telemetría satélite llega al gateway por ESP‑NOW y el gateway la publica en MQTT.
  • Los comandos enviados al broker MQTT llegan al gateway, que los reenvía por ESP‑NOW al satélite destino.
  • Es posible tener múltiples gateways; la coordinación entre gateways se realiza a través de MQTT.

Características Principales

🔌 Conectividad Dual

Soporta comunicación simultánea via WiFi y ESP-NOW para máxima flexibilidad

🔐 Escalabilidad

Puede manejar múltiples nodos satélite mediante ESP-NOW y control remoto vía MQTT

⚡ Tiempo Real

Procesamiento en tiempo real con FreeRTOS para baja latencia

💾 Persistencia

NVS (Non-Volatile Storage) para almacenar configuraciones críticas

⚙️ Componentes del Sistema

1. Gateway WiFi (gateway_wifi.cpp/h)

Responsabilidad

Gestiona la conexión WiFi en modo Station (STA) y la integración con el event loop

Funciones principales:

  • init_sta() - Inicializa WiFi en modo Station
  • is_connected() - Verifica estado de conexión
  • Manejo de eventos de WiFi (conectado/desconectado)

2. Gateway ESP-NOW (gateway_espnow.cpp/h)

Responsabilidad

Implementa protocolo ESP-NOW para comunicación de corto alcance con nodos satélite

Funciones principales:

  • init() - Inicializa protocolo ESP-NOW
  • send_command() - Envía comandos a nodos satélite
  • Callbacks de recepción y transmisión
  • Queue FreeRTOS para procesamiento asíncrono

3. Gateway MQTT (gateway_mqtt.cpp/h)

Responsabilidad

Proporciona interfaz de control remoto via MQTT para integración con sistemas de automatización

Funciones principales:

  • init() - Conecta al broker MQTT
  • publish_sensor_data() - Publica telemetría
  • Suscripción a tópicos de comandos
  • Procesamiento de comandos JSON

4. Protocolo DomoTica (domo_protocol)

Responsabilidad

Define estructuras de datos y tipos compartidos entre gateway y nodos satélite

Estructura principal: DomoMessage_t

typedef struct { uint8_t mac_origen[6]; // MAC del nodo emisor uint8_t tipo_nodo; // Tipo de dispositivo uint8_t pin_afectado; // Pin de GPIO uint8_t estado_solicitado; // Estado del pin float lectura_temperatura; // Temperatura (si aplica) float lectura_humedad; // Humedad (si aplica) uint32_t timestamp_operacion; // Timestamp de la operación } DomoMessage_t;

🔄 Flujo de Trabajo

Secuencia de Inicialización

1️⃣ Inicializar NVS (Non-Volatile Storage)

Prepara el almacenamiento para guardar configuraciones persistentes de WiFi y otros parámetros

2️⃣ Crear Event Loop por defecto

Configura el sistema de eventos de ESP-IDF para manejar eventos asíncrónos

3️⃣ Inicializar WiFi en modo Station

Conecta el ESP32 a la red WiFi usando credenciales configuradas

4️⃣ Inicializar ESP-NOW

Activa protocolo ESP-NOW para comunicación con nodos satélite (requiere WiFi activo)

5️⃣ Conectar a Broker MQTT

Establece conexión con servidor MQTT para control remoto

6️⃣ Loop de Monitorización

Monitoriza estado de conexiones y registra eventos periódicamente

✅ Cómo Agregar Nuevas Tareas

⚠️ Nota importante: Una "tarea" en este contexto puede ser:
  • Una nueva funcionalidad en un gateway existente
  • Un nuevo componente de hardware (sensores, actuadores)
  • Un nuevo tipo de nodo satélite
  • Procesamiento adicional de datos

Opción 1: Agregar Sensor a un Nodo Existente

📊 Ejemplo: Agregar Sensor de Luz

Paso 1: Actualizar estructura DomoMessage_t

// En domo_protocol.h typedef struct { // ... campos existentes ... float lectura_luz; // NEW: Lectura de intensidad de luz uint8_t nivel_bateria; // NEW: Nivel de batería del nodo } DomoMessage_t;

Paso 2: Actualizar código del nodo satélite

// En nodo satélite DomoMessage_t msg = {}; // ... llenar campos existentes ... msg.lectura_luz = ldr_sensor.read_voltage(); msg.nivel_bateria = battery_monitor.get_percentage(); esp_now_send(gateway_mac, (uint8_t*)&msg, sizeof(msg));

Paso 3: Procesar datos en el gateway

// En gateway_espnow.cpp - función espnow_processor_task ESP_LOGI(TAG, "Lectura de Luz: %.1f lux", msg.lectura_luz); ESP_LOGI(TAG, "Batería: %d%%", msg.nivel_bateria);

Paso 4: Publicar en MQTT

// En gateway_mqtt.cpp - publish_sensor_data cJSON_AddNumberToObject(root, "luz", msg.lectura_luz); cJSON_AddNumberToObject(root, "bateria", msg.nivel_bateria);

Opción 2: Agregar Nueva Funcionalidad de Control

💡 Ejemplo: Agregar Control de Brightness

Paso 1: Extender DomoMessage_t

typedef struct { // ... campos existentes ... uint8_t comando_pwm; // NEW: Valor PWM 0-255 uint8_t comando_modo; // NEW: 0=OFF, 1=ON, 2=PWM } DomoMessage_t;

Paso 2: Agregar procesamiento de comandos MQTT

// En gateway_mqtt.cpp - handle_mqtt_command cJSON* pwm_item = cJSON_GetObjectItem(root, "pwm"); cJSON* modo_item = cJSON_GetObjectItem(root, "modo"); if (cJSON_IsNumber(pwm_item) && cJSON_IsNumber(modo_item)) { uint8_t pwm_value = (uint8_t)pwm_item->valueint; uint8_t modo = (uint8_t)modo_item->valueint; ESP_LOGI(TAG, "Control: PWM=%d, Modo=%d", pwm_value, modo); // Enviar comando por ESP-NOW }

Paso 3: Procesar en el nodo satélite

// En nodo satélite DomoMessage_t cmd = {}; // Recibido por ESP-NOW if (cmd.comando_modo == 2) { // PWM mode ledcWrite(PWM_CHANNEL, cmd.comando_pwm); }

Opción 3: Agregar Nuevo Tipo de Nodo

🎛️ Ejemplo: Agregar Nodo de Termostato

Paso 1: Crear nueva estructura de mensaje

// En domo_protocol.h #define NODO_TIPO_SENSOR_TEMP 1 #define NODO_TIPO_SENSOR_HUM 2 #define NODO_TIPO_TERMOSTATO 3 // NEW #define NODO_TIPO_CONTROLADOR_LUZ 4 typedef struct { // ... campos comunes ... uint8_t tipo_nodo; // Identifica el tipo // Payload específico según tipo union { struct { float temp; float hum; } sensor; struct { float setpoint; uint8_t modo; } termostato; struct { uint8_t pwm; } luz; } payload; } DomoMessage_t;

Paso 2: Procesar según tipo en gateway

// En espnow_processor_task switch (msg.tipo_nodo) { case NODO_TIPO_TERMOSTATO: ESP_LOGI(TAG, "Setpoint: %.1f°C, Modo: %d", msg.payload.termostato.setpoint, msg.payload.termostato.modo); break; case NODO_TIPO_SENSOR_TEMP: // ... procesamiento sensor ... break; }

Paso 3: Publicar de forma diferenciada en MQTT

// Usar topics específicos según tipo char topic[80]; snprintf(topic, sizeof(topic), "domotica/nodos/%02x%02x%02x/termostato/setpoint", msg.mac_origen[3], msg.mac_origen[4], msg.mac_origen[5]); esp_mqtt_client_publish(client, topic, payload, 0, 1);

❓ Preguntas Frecuentes

¿Cuál es el rango máximo de ESP-NOW?

Aproximadamente 200-250 metros en línea recta sin obstáculos. En ambientes interiores típicos, el rango efectivo es de 30-100 metros.

¿Cuántos nodos satélite puede manejar el gateway?

Teóricamente ilimitado, pero se recomienda no exceder 50-100 nodos activos simultáneamente por limitaciones de CPU y memoria. El tamaño de la queue de procesamiento es configurable.

¿Puedo usar múltiples gateways en la misma red?

Sí. Cada gateway puede comunicarse con su propio conjunto de nodos satélite. Se pueden coordinar a través de MQTT para crear una red más robusta.

¿Cómo manejo fallos de WiFi?

El gateway implementa reconexión automática. Los datos se encolan localmente en FreeRTOS queue mientras espera reconexión a WiFi.

¿Puedo cambiar el broker MQTT?

Sí. Modifica la URL en main.cpp en la línea donde se inicializa MQTT. Soporta brokers locales y en la nube (HiveMQ, Mosquitto, AWS IoT, etc.)

¿Cómo agrego sensores adicionales?

Ver sección "Cómo Agregar Nuevas Tareas" arriba. En resumen: actualiza DomoMessage_t, procesa en gateway_espnow.cpp, y publica en MQTT.

¿Hay límite en el tamaño de los mensajes?

ESP-NOW soporta máximo 250 bytes por mensaje. La estructura DomoMessage_t debe ser < 250 bytes. Verifica con sizeof(DomoMessage_t)

¿Puedo usar esto en producción?

El código actual tiene stubs MQTT y cJSON para demo. Para producción:

  • Instala esp-mqtt real: idf.py add-dependency esp-mqtt
  • Implementa cJSON completo o alternativa
  • Agrega mecanismos de seguridad (TLS/SSL)
  • Implementa autenticación
  • Prueba exhaustivamente con tus dispositivos

¿Cómo debuggeo problemas?

Usa ESP_LOGI/LOGI/LOGW/LOGE macros. Los logs aparecen en el monitor serial. Para más detalle, aumenta el nivel de log en sdkconfig
