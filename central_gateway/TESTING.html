Central Gateway - Guia de prueba

Pasos concretos para configurar, flashear, observar telemetria MQTT y mandar comandos ESP-NOW a un satelite NodeMCU ESP32-S3 N16R8.

Nota: El flujo típico es: Nodos satélite → (ESP‑NOW) → Gateway → (Wi‑Fi / MQTT) → Broker/Cloud. Los satélites no se conectan a Internet directamente; todas las telemetrías y comandos remotos pasan por el gateway.

1. Que necesitas

  • Una NodeMCU ESP32-S3 N16R8 corriendo central_gateway.
  • Un nodo satelite corriendo satellite_node.
  • Ambas placas alimentadas y cerca para ESP-NOW.
  • Una red Wi-Fi 2.4 GHz.
  • Un cliente MQTT, por ejemplo mosquitto_sub y mosquitto_pub.

Arquitectura y flujo de datos

Resumen del comportamiento por defecto:

  • Los satélites envían telemetría por ESP‑NOW al gateway (no van a Internet).
  • El gateway se conecta a la red Wi‑Fi y a un broker MQTT, publicando la telemetría en domotica/nodos/<mac>/status.
  • Los comandos remotos se publican en domotica/gateway/cmd; el gateway los reenvía por ESP‑NOW al satélite indicado.
En la arquitectura estándar, todo el tráfico nube↔nodo pasa por el gateway. Si necesitas que un satélite tenga acceso directo a Internet, modifica el firmware del satélite para habilitar Wi‑Fi/IP.

Paso a paso de la conexión ESP‑NOW (satélite ↔ gateway)

  1. Arranque: ambos inicializan NVS y el loop de eventos.
  2. Gateway: conecta a la red Wi‑Fi (STA) y arranca ESP‑NOW; queda escuchando tramas entrantes.
  3. Satellite: inicia ESP‑NOW y, si no conoce la gateway, envía probes broadcast en canales 1..13 (barrido) hasta recibir respuesta.
  4. Discovery: si el gateway y el satélite coinciden en canal, la gateway recibe el probe y puede registrar al satélite como peer y enviar un ACK.
  5. Confirmación: al recibir el ACK el satélite registra la gateway como peer y cambia a comunicaciones unicast.
  6. Operación: el satélite envía reportes al gateway y el gateway reenvía a MQTT; el gateway envía comandos al satélite cuando procede.

Logs y mensajes esperados:

  • En el satélite: "Probando canal X para descubrir la Central..." y luego "Central registrada como par".
  • En la gateway: "Tramas recibidas de Nodo: AA:BB:..." y "ACK enviado al nodo ...".

Recuerda: ESP‑NOW requiere que ambos dispositivos estén en el mismo canal 2.4 GHz. El barrido automatizado es útil en pruebas; en despliegues estables, fija un canal común.

Notas adicionales:

  • La gateway emite beacons periódicos mientras no detecte peers; esto ayuda a que satélites que arrancan más tarde la encuentren.
  • El satélite guarda la MAC y canal detectados en NVS para arranques futuros y evitar barridos largos.

2. Configurar gateway

Edita central_gateway/main/gateway_config.h:

constexpr const char* WIFI_SSID = "YOUR_WIFI_SSID";
constexpr const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
constexpr const char* MQTT_BROKER_URI = "mqtt://broker.hivemq.com";

Para la primera prueba podes dejar HiveMQ. Para uso real conviene usar un broker propio con autenticacion y TLS.

El satelite usa el LED RGB integrado WS2812 en GPIO48 para probar comandos sin cableado externo.

5. Ver telemetria desde la red

mosquitto_sub -h broker.hivemq.com -t 'domotica/nodos/+/status' -v

Ejemplo de salida:

domotica/nodos/aa:bb:cc:dd:ee:ff/status {"mac_origen":"aa:bb:cc:dd:ee:ff","tipo_nodo":4,"pin_afectado":48,"estado_solicitado":0,"led_brightness":0,"button_pressed":0,"spi_value":23,"temperatura":25.5,"humedad":60.0,"timestamp":12345}

Copia el valor de mac_origen; es la MAC destino para los comandos.

6. Encender LED RGB del satelite

mosquitto_pub -h broker.hivemq.com -t 'domotica/gateway/cmd' -m '{"mac":"aa:bb:cc:dd:ee:ff","pin":48,"estado":1}'

Resultado esperado: el gateway recibe el comando MQTT, lo reenvia por ESP-NOW, y el LED RGB del satelite queda verde.

7. Apagar LED RGB del satelite

mosquitto_pub -h broker.hivemq.com -t 'domotica/gateway/cmd' -m '{"mac":"aa:bb:cc:dd:ee:ff","pin":48,"estado":0}'

Resultado esperado: el LED integrado se apaga y la siguiente telemetria reporta led_brightness: 0.

8. Leer pulsador del satelite

El satelite lee el BOOT integrado en GPIO0, activo en bajo. Mantene abierta la suscripcion MQTT y presiona BOOT hasta que llegue una telemetria nueva.

"button_pressed":1

Al soltarlo deberias ver:

"button_pressed":0

9. Leer SPI del satelite

SenalGPIO
MOSI11
MISO13
SCLK12
CS10

El valor aparece en telemetria como:

"spi_value":23

Sin un dispositivo SPI conectado, el valor puede no representar una medicion real, pero el campo sirve para probar el camino satelite -> gateway -> MQTT.

10. Formato del comando MQTT

Publicar siempre en domotica/gateway/cmd:

{
  "mac": "aa:bb:cc:dd:ee:ff",
  "pin": 48,
  "estado": 1
}
  • mac: MAC del satelite tomada de mac_origen.
  • pin: para la prueba del LED integrado usar 48.
  • estado: 1 enciende, 0 apaga, 99 representa falla/rojo en el actuador.

11. Problemas comunes

  • Si no conecta a MQTT, revisa SSID, clave y que la red sea 2.4 GHz.
  • Si no ves telemetria, revisa primero el monitor del gateway y confirma que lleguen tramas ESP-NOW.
  • Si el gateway recibe tramas pero MQTT no muestra nada, revisa broker y topico domotica/nodos/+/status.
  • Si el comando no hace nada, copia exactamente el mac_origen de la telemetria.
  • Si ESP-NOW falla, acerca las placas y revisa el canal Wi-Fi del AP.
  • HiveMQ es publico; si hay ruido, cambia a un broker privado o usa topicos mas unicos.
